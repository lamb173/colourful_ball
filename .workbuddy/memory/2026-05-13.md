# 2026-05-13

## Three.js 弹跳球游戏 - 碎裂效果与 Game Over

新增功能：
- 球落到 type 2（三块方形）或 type 3（两块方形）轨道时，检测球颜色 key 与最近方块颜色 key 是否匹配
- 颜色不匹配 → 触发粒子爆炸碎裂效果（60 个 IcosahedronGeometry 粒子，带重力、自转、淡出，持续 1 秒）
- 碎裂完成后展示 Game Over 覆盖层（渐变文字 + 毛玻璃背景）
- "再来一次"按钮重置所有轨道 mesh、粒子、球体和运动状态

关键实现：
- `partColorKeys` 数组保存每个 part 的颜色 key，落地时根据球 X 坐标找最近 part 判断
- `currentBallColorKey` 全局变量追踪当前球颜色 key（初始为 'blue'，落到长直轨道时更新）
- `triggerBurst(pos, color)` 触发爆炸并隐藏球体/光环/阴影圈
- `gameOver` 标志让动画循环只更新粒子，不推进游戏逻辑
- `restartGame()` 清空所有组 mesh 并重新 initGroups()，重置全部状态变量

## 修复 type 3 两块方形必死 bug

问题：回收时两块方形轨道用 `lastLongColorKey` 作为 forceColor，而不是球当前颜色 `currentBallColorKey`，导致两者不同步时两块里根本没有球颜色对应的方块，必死。
修复：
1. 回收时改为 `createDoublePlatform(grp.startZ, currentBallColorKey)`
2. `lastLongColorKey` 初始值从 `COLOR_KEYS[0]('pink')` 改为 `'blue'`（与初始球颜色一致）
3. `initGroups` 里 `prevLongColorKey` 初始值同步改为 `'blue'`
4. `restartGame` 里 `lastLongColorKey` 重置也改为 `'blue'`

## 修复路径连通性 bug（彻底方案 - 段安全色）

问题根源：回收生成的 type 3 用当时的 `currentBallColorKey`，但球到达时颜色可能已因长直轨道而改变。所有运行时偷换颜色的方案都有视觉暴露问题。
最终方案：引入 `activeColorKey`（段安全色），从生成规则层面保证连通：
1. 每次生成长直轨道时 → `activeColorKey = 该轨道颜色`（球到达时也变这个色）
2. 之后生成的 type 3 → `createDoublePlatform(startZ, activeColorKey)`（预先生成安全色）
3. type 2（三块方形）三色全包，天然安全，无需处理
4. 球落地长直轨道变色时 → `currentBallColorKey = activeColorKey = g.colorKey`
5. 删除所有运行时偷换逻辑（`ensureGroupSafe`、`refreshForwardType3`）
6. 删除 `lastLongColorKey`，统一用 `activeColorKey`

关键保证：由于生成顺序严格从前往后，回收时 `activeColorKey` 一定等于球当前/即将到达的长直轨道颜色。type 3 在创建时就包含正确安全色，无需任何后续修正。
